# 전체 수집 리라이팅·백필 5건 확인 (2026-10-13)

수집 리라이팅 상한은 400건, 최소 간격은 6초입니다. 직렬화 및 429 환불/하루 3회 중단을 유지합니다. Gemini 수집/백필은 별도 rewriteProcessCalls로 세며 유료 경로의 MAX_REAL_LLM_CALLS_PER_PROCESS=20은 유지합니다. USE_REAL_LLM=false, DOCENT_WITH_LLM=false입니다. .env는 허용된 일일 상한 줄만 변경했고 커밋하지 않았습니다.

## 대상과 실행

넓은 모드/본문 조건 313건 중 모드 NULL이면서 저장된 rewritten 값이 있는 279건은 보존했습니다. EXCERPT 발췌문은 성공 시 교체하도록 사용자가 허용했습니다. 실제 대상 34건, 호출 간격만 계산한 최소 소요 시간 198초(3분 18초)에 생성·DB 처리 시간이 추가됩니다.

```sh
python3 scripts/backfill_rewrites.py
python3 scripts/backfill_rewrites.py --apply --limit 5
```

처리 5/5, 성공 5, 발췌 유지 0, 429 0, 동시 변경 스킵 0. 저장 ID 339,338,333,320,321. 전체 백필을 실행하지 않았습니다. 실패/429는 기존 DB 값을 유지합니다. REWRITTEN과 출처 불명확한 NULL 모드 저장값은 재생성하지 않습니다. 고정 backfill-rewrites:{newsId} 키로 수집 발췌에 대한 수동 백필을 한 번 시도합니다. 재실행은 성공한 DB 기사와 같은 백필 키를 재생성하지 않으며 429만 재시도합니다.
